# Ритм: нативный проект для iPhone

Версия 2.2 собрана на macOS в GitHub Actions и установлена пользователем на iPhone. Пользователь подтвердил приём пульса Mi Band 6 и сохранность данных при продлении подписи. Версия 2.3 собрана и прошла XCTest в GitHub Actions; приём реальных пакетов шагов требует проверки на устройстве. В 2.4 добавлены тренировки с другом вне плана и обновлён интерфейс. Состояние проверок — в BUILD-STATUS.md.

Приложение SwiftUI открывает встроенный интерфейс из `ritm://app/index.html` через WKWebView. Веб-файлы включены в пакет, компьютер и веб-сервер для открытия интерфейса не нужны. Базовый дневник и сохранённый маршрут доступны без сети. Дополнительная подложка OpenStreetMap требует интернет; без неё остаются точки маршрута. Встроенный интерфейс должен использовать нативный мост для запуска записи; режим Safari/PWA сам по себе не даёт нативной фоновой записи.

## Что реализовано в исходниках

- До первого выполненного подхода доступна кнопка «Сегодня с другом». Отдельная тренировка сохраняет время и заметку, после завершения учитывается в посещаемости и истории. Подходы своей программы не добавляются; силовой прогресс и отметка выполненного дня программы не подменяются. Запись поддерживает удаление, отмену удаления и резервную копию.
- Интерфейс 2.4 использует общие размеры карточек и кнопок, компактные формы, закреплённое действие выполнения подхода и центрированный эскиз маршрута.

- CoreLocation получает GPS при открытом приложении и во время активной записи в фоне, включая блокировку экрана, при разрешениях iOS. Для фона указан режим `location`, показывается системный индикатор геолокации. iOS принимает окончательное решение о доставке обновлений.
- CoreMotion CMPedometer считывает реальные шаги только в активных интервалах пробежки. Без доступа или датчика значение `steps` — `null`. Финальный запрос датчика имеет тайм-аут 5 секунд и сохраняет последние известные реальные показания, если запрос не удался. Из-за задержки датчика последние шаги могут отсутствовать.
- Активная пробежка и вся завершённая история находятся в одном атомарно заменяемом JSON-файле `Documents/RitmNative/runs.json`. Папка исключена из резервной копии iCloud. Защита файла допускает запись при заблокированном экране после первой разблокировки устройства. Ошибка чтения не перезаписывает существующую историю.
- После принудительного закрытия, сбоя или перезапуска приложение восстанавливает последнюю сохранённую пробежку **на паузе**. Нужно явно продолжить запись. Незарегистрированное время и пропущенный участок маршрута не дорисовываются. Принудительное закрытие пользователем останавливает запись; автоматический перезапуск не реализован.
- Точки с плохой точностью (>40 м), отрицательной точностью, неверными координатами, старыми метками времени (>20 с) и временем далеко в будущем (>5 с) отбрасываются. Внутри сегмента отбрасываются обновления чаще 2 секунд и смещения меньше порога 3–10 м с учётом точности; это уменьшает накопление расстояния при стоянии на месте. Крупные скачки фильтруются. Пауза, возобновление и разрыв GPS >20 с начинают новый сегмент; расстояние между сегментами не начисляется.
- Данные пробежек не отправляются из нативного кода в сеть. Встроенная политика страницы разрешает только локальные запросы, необязательные картинки карты OpenStreetMap и поиск продукта по штрихкоду в `world.openfoodfacts.org`. При выборе подложки картографический сервер получает IP и область тайлов; поиск продукта передаёт штрихкод. Внешние ссылки открываются отдельным Safari. Отдельная команда `shareFile` открывает системное меню сохранения/отправки только по действию пользователя; дальнейшее место сохранения выбирает пользователь.
- Bluetooth принимает передаваемый пульс и доступный FEE0-счётчик шагов выбранного Mi Band. Это не полная синхронизация памяти: сон, SpO2, стресс и история браслета не считываются. HealthKit не используется. Калории питания считаются только по введённым порциям и этикеткам. Нативная и браузерная история хранятся отдельно; перенос — через локальную резервную копию.

## Сборка

1. На Windows заново упаковать проверенные интерфейсные файлы: `powershell -File scripts/package-assets.ps1 -Source <путь к outputs/Ritm>`. Скрипт использует список разрешённых файлов. `.local`, сертификаты, сервер, журналы и скрипты запуска не копируются. Нельзя расширять список приватными файлами. При изменении названий интерфейсных модулей обновить список и перепроверить импорт.
2. Запустить workflow `ios-build.yml` в GitHub Actions этого публичного технического репозитория либо перенести эту папку на Mac с Xcode и XcodeGen. Личная программа, история и ключи в репозиторий не входят.
3. Запустить `bash scripts/build-macos.sh`. Сначала создаётся проект Xcode, затем архив устройства и `build/RitmNative-unsigned.ipa` с отключённой подписью. Workflow также проверяет модели и запуск интерфейса на симуляторе; подтверждённые сборки перечислены в BUILD-STATUS.md.
4. Для проверки моделей: после `xcodegen generate` запустить тесты схемы RitmNative на доступном симуляторе iPhone в Xcode. Физические GPS, фон и шаги проверять на настоящем iPhone.

Встроенные файлы подключены как папка ресурсов через `sources` / `type: folder` / `buildPhase: resources` по [официальной спецификации XcodeGen](https://github.com/yonaskolb/XcodeGen/blob/master/Docs/ProjectSpec.md).

**Unsigned IPA требует подписи перед установкой.** Пользователь уже установил приложение через Sideloadly на Windows с личной бесплатной подписью и подтвердил сохранение данных при её продлении. Обновление следует ставить поверх существующего приложения с прежним Apple ID и идентификатором, без удаления. Срок бесплатной подписи ограничен; автоматическое продление выполняет Sideloadly при доступном iPhone. Платная подписка и платный сервер не используются.

## Контракт моста

Только основная страница с origin `ritm://app` может отправлять команды:

```js
window.RitmNativeReply = ({id, ok, data, error}) => { /* сопоставить с запросом */ };
window.webkit.messageHandlers.ritm.postMessage({id: 'request-1', action: 'getRunState', payload: {}});
```

Доступны `capabilities`, `startRun`, `pauseRun`, `resumeRun`, `stopRun`, `getRunState`, `listRuns`, `deleteRun` (для удаления `payload: {id: runId}`). Изменяющие команды блокируются во время завершения запроса датчика. Идентификатор запроса — строка до 128 символов или число. Ответ сериализуется JSON → base64; текст пользователя не подставляется как JavaScript.

Для сохранения резервной копии или календаря есть `shareFile` с `payload: {name,mime,content}`: UTF-8 текст до 64 МиБ, расширение `.json` / `application/json` или `.ics` / `text/calendar`. Имя проверяется и не может содержать путь. Ответ `{presented:true}` означает открытие системного меню, а не успешное сохранение пользователем. Временный файл исключён из резервной копии и удаляется после завершения или отмены меню. Подтверждения JavaScript `confirm()` показываются нативным диалогом.

`startRun`/`pauseRun`/`resumeRun`/`getRunState` возвращают `{status,run,locationAuthorization,locationServicesEnabled,motionAvailable,motionAuthorization,persistenceError}`. Статусы: `idle`, `running`, `paused`. Первый запуск без разрешения запрашивает геолокацию и возвращает понятную ошибку; после выбора разрешения пользователь повторяет начало. При следующем явном начале/продолжении запрашивается повышение до «Всегда», если ранее разрешено «При использовании». `capabilities` не запрашивает разрешений. `stopRun` возвращает завершённую запись; `listRuns` — массив записей от новых к старым.

Запись: `{id,startedAt,finishedAt,seconds,distanceMetres,points,steps,source:'iphone-native'}`. Время — миллисекунды Unix, длительность — секунды активных интервалов. Точка: `{lat,lon,at,accuracy,segment}`. `segment` обязателен для отрисовки разрывов; нельзя соединять разные сегменты линией. Шаги не оцениваются по расстоянию. Удаление истории в приложении не очищает браузерную историю Safari.

## Проверки перед использованием

На Windows доступна команда `python tests/check_carrier.py`: проверяет структуру, защитные условия, разрешения и совпадение пакета с манифестом. XCTest покрывает фильтр GPS, разрывы, расчёт длительности, восстановление и сохранение; тесты XCTest версии 2.2 запускались в GitHub Actions, 28 модельных тестов 2.3 и проверка запуска интерфейса также прошли в GitHub Actions.

На устройстве обязательно проверить: первый запрос геолокации и движения; отказ и последующее разрешение; запись с заблокированным экраном и при переключении приложений; отсутствие расстояния через паузу; пропадание GPS; шаги только в активных интервалах; принудительное закрытие и ручное продолжение после открытия; историю после перезапуска; повторное открытие без сети; фактическую подпись и срок её действия. До этих проверок проект нельзя считать готовым трекером для пробежек.
